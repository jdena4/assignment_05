This assignment mainly taught me about grain, which is what one row of a table stands for. The combined history is one row per person per week, and steps like add_clean_columns and add_roster still follow the lineage rule from last time by adding new columns next to the raw ones. But summarize_employees, hours_grid and pay_by_month build a brand new table at a different grain, one row per employee or one row per month, so they are allowed to look completely different as long as they don't change the history. I also learned to clean a whole column at once with vectorized .str methods instead of apply, like turning "E4" into "E004" with strip, upper, .str[1:] and zfill(3). For dates I had to parse with pd.to_datetime twice, once per format with errors="coerce", and fill the NaT from one pass with the other. The most useful trick was the pivot then melt round trip: pivot_table with fill_value=0 makes a cell for every employee and week, and melt turns those zeros back into rows, which is the only way to see the weeks someone missed. Most of my mistakes were small but caused a lot of failures. My hours_grid was missing reset_index() after pivot_table, so employee_id and display_name were stuck in the index and missed_weeks crashed with a KeyError, failing 7 tests from one bug. I also lost my first function because I didn't save the file before the container rebuilt, and ruff caught a missing blank line and a missing newline at the end of a file. Next time, I will print a table's columns and index after every groupby or pivot to check where the keys ended up, run git diff before committing to make sure my changes actually saved, and run ruff check before every commit.
